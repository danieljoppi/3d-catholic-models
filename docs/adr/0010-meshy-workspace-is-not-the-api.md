# 0010. The Meshy workspace is not the Meshy API

**Status:** Accepted
**Date:** 2026-09-07

## Context

`scripts/meshy.py` was written to pull finished models out of the Meshy
account and drop them in `inbox/`. It was written blind — the session that
wrote it could not reach `api.meshy.ai` at all — so correcting it against real
responses was left to a session that could.

With network access and a working key, the guesses turned out to be close.
Verified on 2026-09-07 against the live API:

| | |
|---|---|
| `GET /openapi/v1/image-to-3d` | 200, a bare JSON list |
| `GET /openapi/v2/text-to-3d` | 200, a bare JSON list |
| `GET /openapi/v1/balance` | 200, `{"balance": 125}` |
| `GET /openapi/v1/text-to-3d` | 404 `NoMatchingRoute` |
| `GET /openapi/v2/image-to-3d` | 404 `NoMatchingRoute` |

But every listing came back empty — `[]` — while the web app's My Assets held
the fifteen Stations reliefs and a Marian statue, all generated days earlier.
The key was not wrong; the balance call answered on the same key.

Meshy's own documentation gives the reason: assets made through the API do not
appear in the workspace, and the two "have separate asset lifecycles with
different expiration rules". There is no documented endpoint that lists or
downloads workspace assets — the OpenAPI surface covers generation, processing,
imaging, 3D printing and balance, and nothing else.

## Decision

Treat the two as separate sources.

`scripts/meshy.py` fetches **API tasks only**, and says so: an empty listing is
reported as an ordinary, expected state naming the workspace split and pointing
at this record, not as an error to be debugged again.

Models generated in the web app come in the way every other outside file does —
exported by hand into `inbox/<collection>/` and drained by `scripts/ingest.py`
(ADR-0008).

## Consequences

The fifteen Stations reliefs already in the workspace cannot be pulled by any
script here. Getting them in is manual: download from My Assets, drop in
`inbox/stations/`, push. That is a real cost, paid once per model.

In exchange nobody spends another session hunting for the endpoint that would
have listed them, and the client no longer reports a healthy empty account as a
failure.

`meshy.py` keeps its value for anything generated *through* the API from here
on — those tasks it can list, name from their prompt, and download unattended,
which is what `.github/workflows/meshy-fetch.yml` automates. API results expire
after about three days, so that fetch has to be reasonably prompt.

## Alternatives considered

**Call whatever endpoint the web app itself uses.** It is not part of the
OpenAPI surface, it authenticates with a browser session rather than an API
key, and it is free to change without notice. Building the pipeline on it would
be building on sand.

**Regenerate the workspace models through the API** so the client can see them.
Correct, automatable, and it pays credits a second time for models that already
exist — and returns different geometry, since generation is not deterministic.
The Stations reliefs in the workspace are the ones that were reviewed.

**Drop `meshy.py`.** It is the only automated path for anything generated by
API later, and it is now verified rather than guessed. Keeping it costs a file.
